--- 3. the harness ----------------------------------------------------------

The image ($S/e1/img) plays the part of the guest's read-only squashfs root: it
carries runsc, busybox, the scripts and five OCI bundles, and it is mounted
read-only, so nothing is written into it during a run.

  bundle-true    ["/bin/busybox","true"]                          (S1 E1/E2)
  bundle-mounts  ["/bin/busybox","sh","-c","cat /proc/mounts; sleep 1"]  (S1 E2)
  bundle-sleep   ["/bin/busybox","sleep","25"]   (S1 E2's was 60; shortened, five
                 variants run it, and the live captures happen within 2 s)
  bundle-hi      ["/bin/busybox","sh","-c","echo hi; ls /"]        (S1 E4)
  bundle-uname   ["/bin/sh","-c","uname -a"]                       (new, E1)

$ $S/e1/build-img.sh
  116M	$S/e1/img

guest-like-ns.sh is S1's E2 file byte for byte (sha256 ed32c2e1…b74aa).
guest-like-ns-procbind.sh is that file with three marked hunks; see its header
and notes.md.

--- 4. item 1: S1's E2 configuration under the busybox applet ---------------

FLAGS, inside, are S1 E2's plus S1 E3's answer:
  --platform=systrap --network=none --ignore-cgroups --rootless \
  --gofer-network-namespace=new
with --root=/run/runsc-state (rw,noexec tmpfs), TMPDIR=/tmp (rw,noexec tmpfs),
`root.readonly: true` in every bundle, and the bundle on the read-only,
exec-permitted image.

$ /bin/busybox unshare -Urmnpf $S/e1/guest-like-ns.sh $S/e1/img \
      /busybox sh /run-inside.sh

  -U -r  user namespace, this caller mapped to uid 0
  -m     mount namespace
  -n     network namespace   (the harness mounts a fresh sysfs, which needs the
                              netns to be owned by the current userns)
  -p -f  PID namespace       (the harness mounts a fresh procfs, which needs the
                              pidns to be owned by the current userns; and runsc
                              needs that procfs — see variant b)
  -> output-01-e2-under-busybox-unshare.txt

--- 5. item 2: the five driver variants -------------------------------------

Each writes the caller's uid_map, gid_map, setgroups and Cap* sets, /proc/mounts
and the check's verdict, then runs bundle-true, bundle-hi and a live bundle-sleep
whose sandbox and gofer are read while they live.

a. $ /bin/busybox unshare -Urmnpf $S/e1/guest-like-ns.sh $S/e1/img \
        /busybox sh /variant-inside.sh
   -> output-02a-Urmnpf-fresh-proc.txt        (= item 1's configuration, compact)

b. $ /bin/busybox unshare -Urmnpf $S/e1/guest-like-ns-procbind.sh $S/e1/img \
        /busybox sh /variant-inside.sh
   -> output-02b-Urmnpf-parent-proc.txt       (no fresh procfs: the driver's one)

c. $ /bin/busybox unshare -Urm $S/e1/guest-like-ns-procbind.sh $S/e1/img \
        /busybox sh /variant-inside.sh
   -> output-02c-Urm-parent-proc.txt          (no pid, no net namespace)

d. $ PFX=$S/e1/img STATE=$S/e1/state-d TMPD=$S/e1/tmp-d \
     /bin/busybox unshare -Ur /bin/busybox sh $S/e1/variant-inside.sh
   -> output-02d-Ur-no-mount-namespace.txt
   This one CANNOT run in the guest-like image: building that image needs a mount
   namespace and -Ur gives none, so every mount(2) is EPERM. It runs on the
   workstation's own root, as S1 E4 case (c) did, and the check there is the
   workstation baseline (53 and then 27 offending mounts), not a verdict on runsc.

e. $ /bin/busybox unshare -Urmnpf --mount-proc $S/e1/guest-like-ns-procbind.sh \
        $S/e1/img /busybox sh /variant-inside.sh
   -> output-02e-Urmnpf-mount-proc.txt        (busybox's own procfs mount)
