The egress ceiling's digest, ticket 22
======================================

197d4aae216ff9c22268fba6646edc3d976e924f4ccec4e8e5461d60f76ab973

That is SHA-256 over the whole of attest/ceiling/ceiling.nft, commentary
included, and since ticket 22 it is:

  * the number every guest built from this source binds into its evidence and
    prints on its console at start ("tunneld: policy digest ..."), where the
    digest of /config/policy.json used to be; and
  * the number an operator puts in a reference value's policy_digest to admit
    such a guest (docs/policy-binding.md).

The commentary is inside the digest deliberately. It is the justification for
every rule under it, and an edit to a justification that did not change the
number would be an edit nobody had to defend.

How it is produced
------------------

The text is compiled into the measured binary, so the two ways of asking are
the binary itself and the workstation tool built from the same source:

  $ cd attest && go build -o /tmp/b/tunneld ./cmd/tunneld
  $ /tmp/b/tunneld -egress print | sed '/^tunneld: EXIT status=/d' > ceiling.nft
  $ sha256sum ceiling.nft
  197d4aae216ff9c22268fba6646edc3d976e924f4ccec4e8e5461d60f76ab973  ceiling.nft

  $ cd attest && go run ./cmd/attest-tool ceiling -digest
  197d4aae216ff9c22268fba6646edc3d976e924f4ccec4e8e5461d60f76ab973

  $ sha256sum attest/ceiling/ceiling.nft
  197d4aae216ff9c22268fba6646edc3d976e924f4ccec4e8e5461d60f76ab973

`-egress print` writes the ceiling and nothing else on its stream; the one line
`sed` removes is the exit status main() prints after run() returns. The three
agree because there is one text: attest/ceiling embeds ceiling.nft, and
TestTheCompiledInCeilingIsTheRecordedOne holds that file byte-identical to
docs/snp/evidence/ticket22/spikes/E3/ceiling.nft, which is the file spike E3
installed and probed. TestTheTextAndTheRulesAreTheSameCeiling holds the text
and the expressions tunneld hands the kernel together, line for line, so the
number names what is enforced and not only what is written.

What it does NOT cover
----------------------

The digest is over the ceiling's description, not over the binary, the initrd
or the image. It says which rule set this guest came up with; the launch
measurement (RTMR2 on TDX, the launch digest on SEV-SNP) is what says the guest
is running the image that carries it. A verifier needs both, which is why the
reference value carries a measurement and a policy_digest rather than either
alone.

A note for the next image build
-------------------------------

No image was rebuilt for this ticket. Two things in it change bytes that are
inside a launch measurement, so the next rebuild moves the reference values:

  * docs/snp/cloud/tdx/init.tdx — the ceiling is installed at step 3, before
    the config device and before the link, and the old step 5 is gone. The
    initrd is measured whole into RTMR2 (docs/tdx-rtmr2-prediction.md), so a
    guest booted from a rebuilt initrd has a different RTMR2.
  * attest/cmd/tunneld and docs/snp/image/init.rootfs — the binary and the
    root filesystem of the SEV-SNP image, which are inside its launch digest.

The allow-list entry moves with them: a set authored for a rebuilt image names
the new measurement and this digest as its policy_digest, which
`attest-tool ceiling -digest` prints without a guest, a key or a boot.
