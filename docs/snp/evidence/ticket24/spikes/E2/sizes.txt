What a 108 MB runsc costs the SEV-SNP image, byte for byte.

Ticket 22's image ($STACK/image-ticket22, recorded in
docs/snp/evidence/ticket22/manifest.txt) against this one
($STACK/image-ticket24). Same firmware, same kernel, same busybox, same build
script but for ticket 24's additions: /usr/bin/runsc, the unshare applet symlink,
the empty /workload directory, and the two init scripts' new text.

The whole cost is in rootfs.img, and it is smaller than the binary that
caused it: squashfs with zstd compresses the 108,668,311-byte runsc into a
9,977,856 -> 85,319,680 byte image, so 75.34 MB of image bought 103.6 MB of
binary. The dm-verity hash tree over it grew with it: 2,416 -> 20,665 data
blocks of 4,096 bytes, the tree starting right after the data in the same file.

initrd.img grew by 849 bytes and cmdline.txt by 2, and neither is runsc: the
initrd's growth is init.initrd's new workload-device block, and the command
line's is the verity data-block count going from four digits to five. runsc is
in the verity root on SNP, not in the initrd — that asymmetry is TDX's, where
the initramfs is the root.

tunneld grew 4,507 bytes between the two builds for reasons that are not this
ticket's (the two tickets are 3 days and several commits apart).
