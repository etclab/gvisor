================ 1. the propagation of / inside 'busybox unshare -Urm' ================
(busybox's usage lists --propagation slave|shared|private|unchanged but names no
 default; a 'shared:' tag on / would mean mounts made inside can propagate out)
$ grep -E ' / / ' /proc/self/mountinfo        # the driver's own, for contrast
32 1 259:8 / / rw,relatime shared:1 - ext4 /dev/md0p1 rw,stripe=64
$ /bin/busybox unshare -Urm /bin/busybox sh -c 'grep -E " / / " /proc/self/mountinfo'
560 559 259:8 / / rw,relatime - ext4 /dev/md0p1 rw,stripe=64
$ /bin/busybox unshare -Urm --propagation unchanged /bin/busybox sh -c 'grep -E " / / " /proc/self/mountinfo'
unshare: can't mount none on / (flags:0x0): Invalid argument

================ 2. does a mount made inside reach the caller? ================
$ mkdir -p $S/e1/vis && /bin/busybox unshare -Urm /bin/busybox sh -c 'mount -t tmpfs t $S/e1/vis; grep vis /proc/mounts'
inside:
t $S/e1/vis tmpfs rw,relatime,uid=253477,gid=253477,inode64 0 0
$ grep -c vis /proc/mounts     # back outside, after it exited
0
(0 means the mount did not propagate to the caller's namespace)
