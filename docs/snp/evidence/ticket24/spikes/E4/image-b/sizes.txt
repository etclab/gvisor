answer in docs/snp/cloud/tdx/init.tdx. The comparison that matters here is not
against ticket 19 — ../image/sizes.txt already did that — but against E4's own

2,097 bytes of shell and comment become 1,044 bytes of gzipped initrd, and that
is the whole of the difference between the image the hardware refused to run a
workload on and this one. The cpio entry list is identical but for the build
directory's name in it: mkdir and chroot are reached through /bin/busybox rather
than through applet symlinks precisely so that no entry has to be added
(build-tdx-image.sh's APPLETS is untouched).
