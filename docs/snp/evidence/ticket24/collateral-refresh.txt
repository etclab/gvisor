Ticket 22's deviation, carried forward
--------------------------------------
The definition of done says "with attest-tool provision fetch". It was curl, as on 2026-09-08
and 2026-09-15, because `attest-tool provision fetch` is the AMD chain tool and only that:

    attest/cmd/attest-tool/provision.go
      usage:
        attest-tool provision fetch -report REPORT.bin -out DIR
        attest-tool provision check -report REPORT.bin -dir DIR

`fetch` takes exactly two flags, reads -report as an SEV-SNP attestation report in ABI form and
calls provision.Fetch to pull the VCEK chain for the platform that report names (ADR-0005). It
has no vendor flag and no Intel mode, so it cannot be asked for a TCB info, a QE identity or a
CRL; the Intel half of provisioning has always been four curl requests, and ADR-0005/ADR-0007
require the documents to be on disk ahead of use, not that one binary put them there. What is
checked is therefore the result rather than the fetch: `attest-tool verify -vendor intel-tdx`
against the refreshed directory, plus the ticket 21 replay. Both are below.

collateral differs between the two:

    $ cd attest && GOPROXY=off go build -o /tmp/attest-tool ./cmd/attest-tool

      REPLAY_LIST=$PWD/verdict-invocations-v2.txt \
      REPLAY_AUTHORED=$PWD/authored \
        ./replay-verdicts.sh /tmp/before /tmp/attest-tool verify     # before the fetch

        diff -q <(tail -n +2 "/tmp/before/${f##*/}") <(tail -n +2 "$f") >/dev/null || echo "DIFF ${f##*/}"
      done
    DIFF 023-tdx-smoke-future.txt
